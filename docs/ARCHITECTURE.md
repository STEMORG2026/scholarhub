# Architecture

ScholarHub is a static browser application. Vite builds React UI and imports the JSON catalog at build time. There is no application server, database, authentication, or shared user store.

```text
index.html → src/main.jsx (entry) → src/App.jsx ─┬→ data/scholarships.json   (records, incl. nationality_scope)
                                                 ├→ src/countries.js  → data/countries.json  (names + ISO codes)
                                                 ├→ src/eligibility.js → per-country verdict
                                                 ├→ src/tracker.js    → deadline countdowns + document checklist
                                                 └→ localStorage (profile, saved IDs, tracked applications, documents, theme)
```

`src/main.jsx` is a three-line entry point that mounts `App`. The split is not cosmetic: `App.jsx` must stay free of mount-time DOM access so that `scripts/render-smoke.mjs` can import and render it in Node. Before v0.25.0 a module-level `createRoot(document.getElementById('root'))` ran on import, which made the component unloadable anywhere but a browser and left every view unrenderable in a test.

## Boundaries

- **Catalog:** versioned-by-convention JSON is reviewed and maintained by contributors; imported statically. A later country-file loader can preserve the record schema.
- **Country data:** `data/countries.json` is the one source of truth for country names. It holds two name spaces — `countries` (real countries and territories, each with an ISO 3166-1 alpha-2 code) and `groupings` (destinations that name a region, such as `Europe`). A grouping is a valid destination but never a valid nationality.
- **Country helpers:** `src/countries.js` derives everything the UI needs from that file, by loop, at module load — the country list for the picker, the destination set, and the flag for a country, computed from its code as regional indicator symbols. There is deliberately **no hand-written per-country flag table**: such a table fails silently (a missing country renders a generic globe), which is why flags are derived rather than stored.
- **Eligibility:** `src/eligibility.js` turns a record's `nationality_scope` and a chosen country into one of four verdicts. It is a pure function, kept out of the component so the six modes can be unit-tested. Two modes (`all`, `listed`) are answerable from the data; the other four (`listed_elsewhere`, `regional`, `agreement`, `unstated`) return **check**, because guessing them would tell a reader they are eligible when the source does not say so.
- **Presentation:** `src/App.jsx` contains views, filtering, local state, and the detail dialog; `src/styles.css` owns responsive styling and light/dark theme. Deadline rendering is provenance-aware: a date is shown only when the record carries one, and always next to the date the source was last checked. A record's `country_notes` entry is rendered only when the reader has selected that country.
- **Verification:** three layers, in increasing authority. `npm test` is the canonical local gate and a *chain* — `node --test` (unit tests against the catalog and the pure modules), then `scripts/validate-catalog.mjs` (catalog integrity), then `scripts/render-smoke.mjs`. The last one loads `App.jsx` through Vite's SSR transform and renders all six views against both an empty and a populated browser; rendering is the only thing that executes a view's branches, so it is the only check that catches a runtime error inside a view. `.github/workflows/ci.yml` then runs that same canonical command on every pull request, so a stage added to the chain is covered remotely without editing the workflow. `npm run check:links` stays manual and out of both, because it is network-dependent by nature.
- **Tracker and documents:** `src/tracker.js` holds the two post-discovery concerns as pure functions. Deadline arithmetic compares **UTC calendar days**, not `Date` instants, so a one-day gap across a daylight-saving shift cannot round to zero; a date that does not parse — including an impossible one such as `2026-02-30`, which `Date.UTC` would silently roll to 2 March — returns `null` rather than `0`, so "unparseable" can never read as "due today". A record with no `deadline` is reported as *no single closing date* and shown with its `deadline_notes`; it is never given an invented countdown, and it is never dropped from the list. The document checklist is a fixed list of twelve items whose *required* subset depends on the reader's degree goal, so a research proposal is optional for a Master's applicant rather than reported missing.
- **Alerts:** the badge counts only what is still actionable — still-open applications whose date is near or gone, plus missing documents. A submitted or decided application whose deadline has passed is counted in the summary but excluded from the alarm. Document alerts begin only once the reader has engaged with the checklist or the tracker, so a brand-new visit carries no badge.
- **Personalization:** simple deterministic profile-fit percentage. It is a sorting/discovery hint, not AI and not an eligibility conclusion — but a programme the reader is not eligible for is scored down rather than recommended.
- **Assistant:** currently an offline explanatory starter which can suggest catalog matches and report how many are open to the reader's country. It does not perform inference or contact an external service.
- **Provider seam:** AI settings separate provider choice from discovery UI, but connection adapters are not implemented. Any future adapter must be explicit, direct from browser, disclose provider processing and never send profile information without a clear user action. Keys must not be stored in a server or repository.

## State and privacy

`scholarhub` uses browser localStorage keys `sh-saved`, `sh-profile`, `sh-tracker`, `sh-docs`, and `sh-dark`. Data stays in that browser profile unless a future opt-in integration sends prompt data to a provider. There is no sync, cross-device backup, or account recovery. Users can clear browser storage to remove the profile, shortlist, tracked applications, and checklist.

`sh-tracker` is a map of catalog id → `{status, addedAt}`; `sh-docs` is the array of document ids the reader has ticked. Both are written on every change rather than behind a Save button, and both are read back defensively: an unrecognised status is treated as the default, and an unrecognised document id is ignored, so a stale or hand-edited value cannot invent state.

The chosen country of origin lives in `sh-profile` and is never sent anywhere; the eligibility verdicts are computed in the browser from the static catalog. Deadline countdowns are computed against the reader's own clock at render time, so a tab left open overnight shows the new day.

## Deployment

`npm run build` emits static files to `dist/`; deploy that folder. For a non-root URL, configure Vite's base path. Fonts load from Google Fonts when network access is available; system fallbacks are declared.

## Known limitations

- Starter catalog is incomplete (50 records) and does not meet the requested 15–25 verified records per country/region. Broader Europe is the only region at the target, and only at its lower bound (15); China holds 5, New Zealand and the United States 4 each, and Brazil, Canada, Japan, South Korea, India and Saudi Arabia were opened with one record each. **Phase 2's last region, Africa, opened in v0.22.0** with the Pan African University scholarship, which spans four institutes in Kenya, Nigeria, Cameroon and Algeria — so it is recorded under `Multiple countries` rather than a single destination. Most records are discovery leads, not confirmed open awards.
- **Eligibility is answered for two of the six modes.** `all` and `listed` give a definitive verdict; `regional`, `listed_elsewhere`, `agreement` and `unstated` report **check** with what to look up. `regional` has been closed where a provider publishes its list — Australia Awards, the Manaaki Thematic scheme and the NL Scholarship are now `listed` against transcribed country lists — and remains `regional` only where the rule genuinely cannot be enumerated: the **Pan African University Scholarship**, whose eligibility is "African countries and the African Diaspora". The Diaspora is not a country list, so that record reports **check** for every reader, including readers in Africa. Resolving it needs the AU's own membership list plus a defensible reading of "Diaspora", not a continent table — a provider's "Africa" is not a continent.
- Deadlines are recorded only where an official page publishes a single closing date (**13 of the 50 records**, verified 2026-10-07). Cycles that are a window, field-split, or country-specific carry `deadline_notes` instead. Comparable award amounts, acceptance rates, and applicant counts are not maintained. No popularity counter, geolocation ranking, or roadmap export is implemented.
- **Reminders never leave the browser.** The tracker computes countdowns and raises in-app alerts from the catalog and the reader's own clock. There is no notification-permission request, no service worker, no email or push, and nothing is scheduled to run while the tab is closed — a "deadline reminder" here means the app telling the reader when they open it. Two of the dated records (`pec-pg-brazil`, `pan-african-university`) hold a closing date from a completed cycle, so the tracker reports them as passed even though a later call may be open; re-verifying them is a data pass.
- **The document checklist is a fixed list of twelve ordinary items, not any scheme's real requirement set.** No scheme's document set is knowable from this catalog, and the interface copy says so. It is a personal tracker the reader fills in, not an authoritative requirements list — which is why it never blocks or gates anything.
- Link liveness is not part of `npm test`. Run `npm run check:links` (needs the network). It can only prove that a URL resolves — never that the page still says what the record claims.
- **CI is not a required status check.** `.github/workflows/ci.yml` reports a `verify` context on every pull request, but branch protection requires only a pull request — not a passing check. A red pipeline can therefore still be merged. Registering `verify` as a required status check is a deliberate decision left to the owner, because it changes the merge gate for everyone.
- Below 850px the sidebar collapses to an icon-only rail. There is no slide-out drawer.
- Accessibility: contrast is measured to WCAG AA in both themes, and visible focus, dialog keyboard handling (focus trap, Escape, focus restore), labelled controls and live regions are in place. The tracker and checklist added **31 more measured colour pairs** in v0.24.0 (all ≥ 4.5:1 for text, ≥ 3:1 for the progress bar), and the countdown chips carry their urgency in words as well as colour so the state does not depend on distinguishing tints. A `prefers-reduced-motion` guard is in place and verified by emulating the media query (40 perceptible transitions → 0). The app contains no `@keyframes` and no `animation` property, so the guard covers the hover transitions and anything added later rather than an existing animation. A screen-reader pass with real assistive technology is not yet done.
- The eligibility badge carries its reason in a `title` attribute and repeats it in the detail dialog; the reason is not yet exposed as screen-reader text on the card itself.
- AI provider adapters, model test, API key handling, cloud model calls, local model runtimes, and cost estimates are not implemented.
- Content status may be `verify`; official pages are authoritative and may change independently.
